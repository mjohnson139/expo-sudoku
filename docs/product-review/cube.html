Cube Scramble

Current functionality, controls and states · redesign inventory

Current purpose: a companion for the physical 3×3 cube: generate and inspect scrambles, record/replay solves, mark method stages, curate algorithms and methods, and derive practice progress.

3. Starting and managing solves

Method picker.

Attempt menu.

Method picker

  • Preset choices: Beginner LBL, CFOP and Roux, each with its stage summary.
  • User methods marked “Use for new solves” join the list.
  • Freeform creates a solve with no prescribed rail and allows authored phase labels.
  • Selection creates the solve immediately; there is no separate confirmation screen.

Solve-card information

  • Name, method, saved/edited recency and completion/in-progress state.
  • Stage summary derived from markers rather than stored ranges.
  • Tagged algorithm-run names can appear in solve detail/playback.

7. Cube-first algorithm workbench

Workbench at authored-start step.

Flow

  1. Start from solved and turn the cube to the position where the algorithm begins.
  2. Lock the authored starting state, or explicitly derive it later/use the inverse.
  3. Write the algorithm with native finger turns, move pad, or paste notation.
  4. Scrub/play the result and tap the shared 3D preview to return to the start.
  5. Save name and stage assignments through the shared save sheet.
CapabilityWhy it exists
Authored setupAn inverse is not always the actual position from which the player practices.
Inverse fallbackOlder/pasted algorithms still get a deterministic starting case.
Large cube + compact previewSeparates active authoring from the stable reference state.
Shared transport/track/padKeeps solve and workbench notation behavior aligned.

9. Journey

Fresh journey.

User variant and derived progress.

  • Preset order is Beginner LBL → CFOP → Roux.
  • User variants sit immediately after their source; “Yours” identifies them.
  • Stages and methods are Done, Open or Locked.
  • Three demonstrations complete a stage; gate copy names prerequisite and remaining locks.
  • A shipped preset demonstration requires its locked boundary to pass a stage-specific cube-state check.
  • A user stage has no pretend predicate; a genuine lock counts and the card says it is unverified.
  • At most one matching marker per stage per solve counts.
  • Progress is derived from the last 100 live solves. Delete/edit the evidence and progress rolls back.
No journey progress record exists. The screen replays each live solve once, consumes its stage-check matrix and projects cards.

Corrupt/older saveCollections sanitize independently by shape; absent newer fields become empty rather than requiring migration.

Storage vocabulary

{ scramble, favorites, solves, algorithms, methods, workspace }. A solve includes scramble, name, method, orientation, notation, phase markers, tagged runs and timestamps. Phase ranges and journey progress are derived.

11. Product/design discussion prompts

Primary job: Is Cube Scramble chiefly a scramble viewer, a solve recorder, an algorithm notebook, a method coach, or a journey? Today it is all five.
Novice versus expert: Beginner LBL and locked progression coexist with notation-heavy authoring, slice/wide moves and reciprocal stage assignments. Are these one audience?
Navigation: The solve list is the door to Algorithms; Algorithms is the door to Methods and Journey. Should these be peer destinations, progressive disclosure, or separate modes?
Physical/digital relationship: Which actions should happen on the real cube, the rendered cube, the pad or text? Web and native currently differ.
Evidence/progress: Is “three verified locked boundaries” the desired measure of learning, and should deleting a solve really erase progress?
Screen density: Cube size was protected by strict point budgets, producing drawers, sheets and icon doors. A redesign can reconsider the whole hierarchy rather than shuffle those controls.
Personal library: Are algorithms and user methods core user-generated content worthy of a dedicated home, or advanced tooling behind practice?
Do not lose in redesign: valid move notation, physical cube colour fidelity, orientation’s three states, one writer per collection, phase markers as span starts, solve playback, edit rollback, user/preset predicate distinction, native back/edge gestures, and authored data persistence.
